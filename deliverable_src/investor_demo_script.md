# Joita Investor Demo Script

## Goal

Deliver a 3 to 5 minute walkthrough that makes Joita feel sharp, focused, and investable.

Do not try to explain every feature. Show one clean trust loop:

1. farmer enrolled
2. parcel mapped offline
3. live evidence captured
4. operator verifies
5. payout is triggered
6. investor sees the audit trail

## Before You Record

- Open `deliverable_src/investor_showcase.html`
- Open the Figma prototype
- Keep `ER_Diagram.pdf` nearby only for technical follow-up, not as your main screen
- Practice the transition between the prototype and the showcase so it feels intentional

## 30-Second Opening

"Joita is an offline-first MRV and payout workflow for fragmented Indian farms. We help field programs capture trusted on-site activity, verify it against parcel-aware evidence rules, and connect that proof all the way to farmer payout and investor visibility."

## Core Pain

"Today, the weak point is not ambition. It is trust. Field evidence is often fragmented, connectivity is unreliable, payouts become manual, and investors cannot easily see how a claimed event became a financial outcome. Joita fixes that chain end to end."

## Recommended Screen Flow

### 1. Start on the investor showcase hero

Say:

"The simplest way to understand Joita is this: trust every farm event before you pay a rupee."

Pause on:
- offline-first
- tamper-evident proof
- payout-linked outcomes

### 2. Move to the workflow section

Click through the six steps slowly.

Say:

"We start with one named farmer, not an abstract data point. Then the parcel is captured offline, so weak connectivity does not break the workflow. Evidence is live and geotagged, not uploaded later from a gallery. Operators review everything in one audit timeline. Only then does payout move. And investors can drill back through the same proof chain."

### 3. Open the prototype

Narrate the click-through as if the workflow is already in use:

- "The field agent starts a visit."
- "The parcel is mapped even under weak signal."
- "A live proof event is captured on-site."
- "The operator sees the event in context."
- "The payout state becomes visible."

Do not over-explain UI mechanics. Keep the narration about trust and operational clarity.

### 4. Return to the showcase trust moat

Say:

"The moat is not just software polish. It is the combination of offline field reliability, tamper-evident proof, and payout workflows tied to verified events."

### 5. Close on India-first execution

Say:

"Joita is designed for Indian field reality from day one: low-end Android hardware, PSP-backed payout rails, clear data boundaries, and future hooks for government-linked verification inputs without overbuilding the MVP."

## 30-Second Close

"We are not trying to be a generic climate platform. We are building trusted offline proof and payout infrastructure for field operations in India. If that chain works cleanly, everything else becomes easier to believe."

## Q and A Anchors

If asked about defensibility:

"The defensibility is the proof chain: parcel-aware evidence, tamper-evident event history, and payout linked to verified operational state."

If asked about why now:

"The market does not need more abstract dashboards. It needs trust infrastructure that works in real field conditions."

If asked about scope:

"The first milestone is intentionally narrow: one clean loop, shown beautifully and built credibly."

If asked about expansion:

"Adapters, satellite QA, and registry workflows are natural next layers, but they only matter once the field truth loop is proven."
